> ## ⚠️ 운영 주의 — 작업 전 반드시 읽을 것
>
> **1. `git push` = 즉시 라이브 반영입니다.**
> `laezer-landing.netlify.app`이 이 레포에 GitHub 자동배포로 연결돼 있습니다.
> 커밋은 자유롭게, **push는 의도적으로**. 배포 절차·롤백은 **[DEPLOY.md](DEPLOY.md)** 참조.
>
> **2. 같은 소스를 Netlify 사이트 2개가 서빙합니다 — 사고 나기 쉬운 구조입니다.**
>
> | 사이트 | 방식 | 위험 |
> |---|---|---|
> | `laezer-landing.netlify.app` | GitHub 자동배포 | — |
> | `laezer.netlify.app` | netlify CLI 직접배포 | **레포를 거치지 않아 소스에 흔적이 안 남음** |
>
> 한쪽만 배포하면 두 사이트 내용이 어긋납니다. 실제로 **2026-10-04 시점에 레포 HEAD(`83d78f8`)와 라이브 배포본이 달랐습니다** — 언어 선택기 링크가 레포는 `index_kr.html`, 라이브는 `/index_kr`. 누군가 레포를 거치지 않고 배포한 흔적입니다.
>
> **정리 방안 (미실행 — 결정 필요):**
> - **A안 (권장) · 하나로 통합**: `laezer`를 폐기하거나 `laezer-landing`의 도메인 별칭(domain alias)으로 전환. SSOT가 레포 하나로 정리되고 드리프트가 구조적으로 불가능해집니다. 외부에 `laezer.netlify.app` 링크가 배포돼 있다면 그쪽에 리다이렉트만 걸면 됩니다.
> - **B안 · 역할 분리**: `laezer-landing` = 프로덕션(레포 자동배포 전용, CLI 배포 금지), `laezer` = 스테이징/프리뷰 전용으로 명시. 다만 **규율에 의존**하므로 A안보다 약합니다.
> - 어느 쪽이든 **두 사이트에 같은 프로덕션 콘텐츠를 각각 수동으로 올리는 현재 방식은 중단**하는 것이 좋습니다.
